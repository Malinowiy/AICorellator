ADR-001: Hybrid Scanning Model with Targeted Scans and Global Diff

Status: Accepted
Date: 2026-10-07
Deciders: AICorellator core team

Context

AICorellator correlates findings from multiple scanners (NeuralScan, agent-audit-kit, garak) into a unified graph of AI infrastructure. Each scanner operates on a different semantic layer:

NeuralScan discovers infrastructure entities: LLM endpoints, MCP servers, tools, agents, sinks.
agent-audit-kit analyzes code and configuration files: tool poisoning, secret exposure, taint analysis.
garak probes model behavior: prompt injection resistance, jailbreak susceptibility.
The naive approach — run every scanner against the entire machine, then merge results — has two problems:

Mapping problem. Findings from agent-audit-kit carry a filePath (e.g. finbot/mcp/servers/findrive/server.py). Nodes in the graph carry tool identifiers (e.g. claude-catalog:gmail). Correlating the two requires heuristic matching, which is error-prone and produces false merges.
Noise. A global scan surfaces findings in files that are not part of any discovered entity — tests, documentation, unrelated tooling. These findings dilute the graph and force the correlator to filter aggressively.
Decision

We adopt a hybrid scanning model with three phases:

Phase 1 — Discovery

NeuralScan runs once and produces the set of infrastructure entities. This is the only scanner that is inherently global: it must see the whole host to enumerate what exists.

Phase 2 — Targeted scanning

For each discovered entity, a routing rule selects which scanner to run and on what target:

Entity type	Scanner	Target
mcp_server	agent-audit-kit	server directory
agent	agent-audit-kit	agent directory
llm_endpoint	garak	endpoint URL
cloud_connector	—	skipped (no local code)
sink	—	skipped (abstract)
Findings from targeted scans are attached directly to the entity node. No mapping is required: the scanner was pointed at the entity, so its findings belong to that entity by construction.

Each targeted scan records a covered_files set: every file the scanner traversed, not only files where findings were produced. This is the coverage claim.

Phase 3 — Global diff

Each scanner also runs globally, once. Global findings are filtered against the union of all covered_files from Phase 2:

text
global_diff = [f for f in global_findings if f.filePath not in covered_files]
The result is the orphan findings set — findings in files that no targeted scan covered.

Consequences

Positive

Mapping problem eliminated for targeted findings. Findings from a scan of finbot/mcp/servers/findrive/ belong to the findrive node. No heuristic matching is involved.
Global scans become a delta, not a duplicate source. They surface only what targeted scans missed.
Orphan findings become a signal. An empty orphan set means NeuralScan covered everything the scanner sees. A non-empty orphan set means NeuralScan missed entities — a gap in discovery, not a gap in the scanner.
Graph stays clean. Attached findings belong to nodes. Orphan findings are kept separate and passed to the correlator as a distinct block.
Routing is explicit and extensible. Adding a new scanner means adding a routing rule, not rewriting the merge logic.
Negative

Requires covered_files tracking. Each targeted scan must report the set of files it traversed, not only the files where it found issues.
Requires a routing layer. The mapping from entity type to scanner and target must be maintained.
Multiple scanner invocations. N entities means up to N targeted scans, though each is small and parallelizable.
Neutral

Global scan still runs. It is not eliminated, only redefined as a diff source.
Orphan findings are not attached to nodes. They are passed to the correlator as a separate block. The correlator may still connect them semantically — e.g. by recognizing that orchestrator.py invokes the findrive tool — but this connection is made by the LLM, not by the graph.
Alternatives considered

Alternative A — Global-only scanning with heuristic mapping

Run every scanner globally, then map findings to nodes by matching filePath to node identifiers.

Rejected. The mapping is heuristic and produces false merges. Two tools named gmail under different agents (claude-catalog:gmail and chatgpt-catalog:gmail) cannot be distinguished by filename alone. Findings would be attached to the wrong node, producing false exploit chains.

Alternative B — Two-phase model without global diff

Run NeuralScan, then run targeted scans only. Skip global scans entirely.

Rejected. Global scans surface findings outside discovered entities. Without them, AICorellator would be blind to issues in shared infrastructure, orchestration layers, and any component NeuralScan does not recognize as an entity. The global diff makes these gaps visible.

Alternative C — Findings as a separate layer, not attached to nodes

Keep all findings in a flat list, pass them alongside the graph to the correlator, and let the LLM associate them.

Rejected. This loses the structural guarantee that a targeted finding belongs to a specific node. It also forces the LLM to perform the association, which is exactly the kind of heuristic work that should be deterministic.

Notes

The hybrid model does not require that every scanner supports targeted invocation. If a scanner is global-only, its output is treated entirely as orphan findings. The model degrades gracefully: a scanner that cannot be targeted simply contributes to the diff set rather than to attached findings.
