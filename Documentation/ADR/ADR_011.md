# ADR-0011: Framework Detectors

**Status:** Proposed
**Date:** 2026-10-12
**Context:** Phase 2+ — generalizing classification

---

## Context

Classification is hardcoded for FinBot. On LangGraph, CrewAI,
AutoGen, OpenAI Agents SDK, Semantic Kernel, FastMCP — the graph
is nearly empty.

We need multi-level classification that resists obfuscation and
works across different AI frameworks.

---

## Decision

**Three classification levels:**

1. **Framework detectors** (exact, for known SDKs).
2. **Capability extractors** (from AST calls — ADR-0009).
3. **Structural heuristics** (behavioral patterns).

**Fallback:** name-based heuristics (current) — if nothing else
matches.

---

## Level 1: Framework Detectors

**One detector per framework.** Works by imports and API patterns:

| Framework | Signature | What it finds |
|---|---|---|
| **LangChain** | `from langchain.agents import`, `AgentExecutor` | Agents, tools, LLM clients |
| **LangGraph** | `from langgraph.graph import StateGraph` | Nodes, edges, conditional routing |
| **CrewAI** | `from crewai import Agent, Task, Crew` | Agents, tasks, tools |
| **AutoGen** | `from autogen import ConversableAgent` | Agents, group chats |
| **OpenAI Agents SDK** | `from openai.agents import Agent, Runner` | Agents, handoffs, guardrails |
| **Semantic Kernel** | `import semantic_kernel as sk` | Plugins, functions, planners |
| **MCP SDK (Python)** | `from mcp import Server`, `@server.tool()` | MCP servers, tools, resources |
| **MCP SDK (TS)** | `from @modelcontextprotocol/sdk` | Same for TS |
| **FastMCP** | `from fastmcp import FastMCP` | MCP servers, tools |
| **FastAPI** | `@router.get`, `@app.post` | Entry points (HTTP routes) |

**What it gives:**
- Exact classification **without obfuscation** — imports cannot be
  hidden.
- **Semantics** — the detector knows that `AgentExecutor` is an
  agent, not just a class.
- **Untrusted source detection** — RAG configs, MCP declarations.

### Modular Loading

Detectors are modular, loaded one at a time. The user selects which
frameworks to enable:

```
aicorellator scan --target ./app --frameworks langchain,langgraph,fastmcp
```

If a detector is not enabled, classification falls through to
capabilities or structural heuristics.

### Version Support

Each detector declares a supported version range:

```python
class LangChainDetector(FrameworkDetector):
    name = "langchain"
    supported_versions = ">=0.1,<1.0"
```

If the detected framework version is outside the range, a warning
is logged and detection proceeds **at the user's risk**.

## Level 2: Capability Extractors

From ADR-0009. Extracted from AST calls, not names.

---

## Level 3: Structural Heuristics

**Behavior instead of names:**

- Class with `calls_llm + invokes_tool + delegates_to` → `agent`.
- Class with `executes_shell` or `executes_code` → `sink`.
- Function with `http_ingress` → `entry_point`.
- Class with `reads_untrusted` → candidate untrusted-source receiver.

## Architecture

```
src/aicorellator/parsing/
├── framework_detectors/
│   ├── __init__.py
│   ├── base.py                 # FrameworkDetector interface
│   ├── langchain.py
│   ├── langgraph.py
│   ├── openai_agents.py
│   ├── fastmcp.py
│   ├── mcp_python.py
│   └── (later) crewai.py, autogen.py, semantic_kernel.py, mcp_ts.py
├── capability_extractor.py     # ADR-0009
├── structural_heuristics.py    # Level 3
└── classification.py           # Orchestrator: try 1 → 2 → 3 → fallback
```

## Implementation Order

1. **LangChain + LangGraph**
2. **OpenAI Agents SDK**
3. **FastMCP + FastAPI** (entry points)
4. **MCP SDK (Python)**
5. Further detectors on request

---

## Testing

Each detector requires a test project. Generating and maintaining
these is a burden.

**Approach:** generate a synthetic project per framework with a
minimal agent + tool + entry point, and assert that the detector
finds the expected nodes and edges.

Tests for LangChain, LangGraph, OpenAI Agents SDK, FastMCP are
written alongside their detectors.

---

## Consequences

### Positive

1. System works across different AI frameworks.
2. Obfuscation-resistant (imports cannot be hidden).
3. Semantics (framework knows what an agent is).
4. Detectors are isolated — can be added one at a time.
5. User can enable only the frameworks they need.

### Negative

1. Each detector is a separate module (~200-300 lines).
2. Test projects per framework are needed.
3. Framework APIs change — detectors require maintenance.
4. Version drift requires warnings, not silent failures.

### Neutral

1. **Fallback to name-based heuristics remains.**
2. **AAK findings** remain a separate data source.

---

## Not in Scope

- Detectors for **unknown** custom frameworks.
- **Runtime** detection (static only).

---

## Decision

**Add modular framework detectors as Level 1 of classification.
Detectors are user-selectable and versioned. Implementation order:
LangChain + LangGraph, OpenAI Agents SDK, FastMCP + FastAPI,
MCP SDK (Python). Synthetic test projects are generated per
framework.**
