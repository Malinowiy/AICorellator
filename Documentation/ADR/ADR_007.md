# ADR-0007: Guardrails as First-Class Graph Nodes

**Status:** Proposed
**Date:** 2026-10-10
**Context:** Phase 1 — Parsing and classification

---

## Context

While parsing FinBot CTF (a reference AI system), a distinct
component was found that the Phase 0 graph model did not account
for: **guardrails**. These are policy enforcement points that sit
between an agent and the tools it can call, filtering or modifying
the interaction.

Without modeling guardrails as first-class nodes, chain semantics
break in three ways:

1. A chain `agent → tool → sink` looks exploitable, but if a
   guardrail sits between agent and tool, the chain is blocked.
2. Bypassing a guardrail (as in FinBot CTF) is a distinct attack
   step that the graph cannot represent.
3. Phase 3 (LLM chain evaluation) cannot judge exploitability if
   it does not see the enforcement layer.

---

## Considered Options

### Option A: Model guardrails as `sink` nodes

Treat a guardrail as another kind of sink. Simple, no schema
change.

**Rejected:** semantically wrong. A guardrail is not a dangerous
action — it is a defensive control. Conflating them breaks chain
semantics and misleads the LLM during evaluation.

### Option B: Model guardrails as `tool` nodes

Treat a guardrail as a tool with a filter attribute. No schema
change.

**Rejected:** guardrails are not callable by the agent. They are
infrastructure, not capability. This distinction matters for
attack chain analysis.

### Option C: Add `guardrail` as a new node kind

Extend the schema. New kind, new edge kind, same table.

**Accepted.**

---

## Decision

**Add `guardrail` as an eighth node kind, and `guards` as a fifth
stored edge kind.**

### Node kind

| Kind | Description |
|---|---|
| `guardrail` | A policy enforcement point between agent and tool |

### Edge kind

| Kind | Description |
|---|---|
| `guards` | Guardrail protects an agent or a tool |

### Guardrail attributes

| Attribute | Values | Description |
|---|---|---|
| `policy` | `prompt_injection`, `pii`, `tool_allowlist`, `rate_limit`, `unknown` | What the guardrail filters |
| `enforcement_point` | `pre_tool_call`, `post_llm_response`, `pre_agent_step`, `unknown` | Where it sits in the flow |
| `source_file` | path | Where it was found |

### Derived edges (NOT stored)

| Derived kind | Meaning |
|---|---|
| `bypassed_by` | Reverse of `guards` — a tool or agent that bypasses the guardrail |
