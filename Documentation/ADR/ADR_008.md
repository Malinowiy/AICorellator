# ADR-0008: Working Directory Layout

**Status:** Proposed
**Date:** 2026-10-10
**Context:** CLI tool needs a place for its state

---

## Context

AICorellator runs as a CLI tool. It needs to store:

- SQLite graph database
- Reports (current + archives)
- TSA cache
- Logs

Where exactly to store them is not fixed. Without this decision,
neither `write_bundle` nor the CLI can be implemented.

---

## Considered Options

### Option A: alongside the target (`<target>/aicorellator_data/`)

**Pros:** location is close to the data.
**Cons:** AICorellator modifies a foreign repository — bad for a
security tool. Target systems are often read-only. Target systems
may lack write permissions.

### Option B: in the current directory (`<cwd>/aicorellator_data/`)

**Pros:** predictable, does not modify the target, easy to find.
**Cons:** if launched from different places — different workdirs.

### Option C: in `~/.aicorellator/`

**Pros:** global, like Docker.
**Cons:** not our style, conflicts when working with multiple
projects, a security tool should not write to the home directory
by default.

---

## Decision

**Option B.** The default working directory is
`<cwd>/aicorellator_data/`. It can be overridden with the
`--workdir <path>` flag.

### Naming

`aicorellator_data` was chosen for three reasons:

1. **Snake_case** — matches the project's Python style.
2. **Clearly owned by the tool** — the `aicorellator_` prefix
   unambiguously identifies it.
3. **Not hidden, does not conflict with the package name** —
   `src/aicorellator/` is code, `./aicorellator_data/` is state.

Rejected options: `.aicorellator/` (hidden), `aicorellator/`
(conflicts with the package name), `aicorellator_workspace/`
(too long), `rundata_aic/` (non-obvious abbreviation),
`data/` (too generic).

### Layout

    aicorellator_data/
    ├── aicorellator.db           # SQLite graph
    ├── reports/
    │   ├── current/
    │   │   ├── report.md
    │   │   └── chains.json
    │   └── 20261010_203045/      # archived report
    │       └── ...
    ├── cache/
    │   └── tree-sitter/          # TSA index cache
    └── logs/
        └── aicorellator.log

### Behavior

- Workdir does not exist → create it (`mkdir -p`).
- Workdir exists → use it.
- `--clean` → delete contents, recreate from scratch.
- `--workdir <path>` → use the given path.

### No separate `--db` flag

**The database is not addressed separately.** The single point of
control is the workdir. The CLI knows the database lives at the
fixed path `<workdir>/aicorellator.db`. There is no `--db` flag.

This ensures the state is always coherent: if the user specifies
a workdir, they get the database, reports, and cache together.
Splitting them would be a source of errors.

### Naming of the DB file

Always `aicorellator.db` inside the workdir.
One workdir — one project. Different projects → different workdirs.

### What is NOT in the workdir

- The target's source code — not ours.
- The target's `.env` — stays with the target; we read it through
  discovery.

### `.gitignore` in the target

If AICorellator is run inside the target's git repository, the user
should add the following line to the target's `.gitignore`:

    aicorellator_data/

This is **not our responsibility** — we do not modify foreign
`.gitignore` files. It is documented in the README.

---

## Consequences

### Positive

1. AICorellator does not modify target repositories — it works
   only in its own directory.
2. Predictable location of state.
3. Easy to remove all state: `rm -rf aicorellator_data/`.
4. `--workdir` allows explicit control over the location.
5. Single point of control — the workdir, with no split between
   database and reports.

### Negative

1. If launched from different CWDs — different workdirs. The user
   must be careful or use `--workdir`.
2. Not a hidden directory — visible in `ls`, but this is
   intentional: hidden directories hinder diagnostics.

### Neutral

1. The user may specify `--workdir` to centralize state outside
   the target repository.

---

## Decision

**The default workdir is `<cwd>/aicorellator_data/`. It can be
overridden with `--workdir <path>`. The `--clean` flag resets it.
There is no separate `--db` flag — the database always lives at
`<workdir>/aicorellator.db`.**
